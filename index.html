Tema 01 · Introducción

Gestores de Base
de Datos (DBMS)

📖 Definición y Propósito
¿Qué es un DBMS?

Un DBMS (Database Management System) es un software especializado que permite definir, crear, manipular y administrar bases de datos. Actúa como intermediario entre los datos almacenados y los usuarios o aplicaciones que los utilizan, asegurando que la información pueda consultarse y modificarse de manera consistente y segura.

Un DBMS no es solo un repositorio de información, sino un sistema integral que organiza, protege y facilita el uso de los datos.
⚙️ Funciones Principales
El propósito central incluye:
✦
Definición de estructuras: creación de tablas, relaciones, índices y esquemas.
✦
Manipulación de datos: consultas, inserciones, actualizaciones y eliminaciones.
✦
Gestión de seguridad: asignación de privilegios y control de usuarios.
✦
Garantía de integridad: reglas y restricciones para asegurar coherencia.
✦
Soporte de concurrencia: manejo del acceso simultáneo de múltiples usuarios.
✦
Mecanismos de recuperación: restauración del sistema tras fallos o pérdidas de datos.
🏢 Importancia en la Gestión
¿Por qué son esenciales?

Los DBMS constituyen el núcleo tecnológico de cualquier sistema moderno, desde pequeñas aplicaciones hasta complejas infraestructuras de Big Data. Garantizan eficiencia, mejoran la seguridad, aseguran integridad, favorecen la colaboración, soportan la toma de decisiones y se adaptan al crecimiento.

Tema 02 · Historia

Evolución Histórica
de los DBMS

📅 Línea del tiempo
60s
Primeros modelos jerárquicos y en red
Se introducen sistemas de archivos jerárquicos (IMS de IBM) y en red (IDMS). Eficientes para estructuras simples, pero rígidos y difíciles de mantener.
70s
Modelo relacional — Edgar F. Codd
Investigador de IBM propone el modelo relacional, organizando datos en tablas con filas y columnas. Se introduce el lenguaje SQL, que permitió mayor flexibilidad y accesibilidad.
80s
90s
Consolidación de RDBMS comerciales
Se popularizan Oracle Database, DB2 y SQL Server. Surgen DBMS de código abierto como MySQL y PostgreSQL, accesibles a comunidades de desarrolladores.
XXI
NoSQL y DBMS en la nube
Los sistemas NoSQL (MongoDB, Cassandra, Neo4j) responden a la necesidad de manejar datos no estructurados y grandes volúmenes. La computación en la nube amplía la disponibilidad y escalabilidad con Amazon RDS, Google Cloud SQL y más.
🔵 Tipología de Gestores
Relacionales (RDBMS)

Basados en el modelo propuesto por Codd. Almacenan datos en tablas con relaciones. Ejemplos: Oracle, SQL Server, MySQL, PostgreSQL. Ventajas: integridad, soporte a transacciones, lenguaje estandarizado SQL.

🟡 No Relacionales (NoSQL)
Diseñados para datos no estructurados

Tipos: documentos (MongoDB), clave-valor (Redis), grafos (Neo4j), columnas (Cassandra). Ventajas: escalabilidad horizontal, flexibilidad de esquemas, alto rendimiento.

🟢 Híbridos o Multimodelo
Lo mejor de ambos mundos

Integran modelos relacionales y no relacionales. Ejemplos: ArangoDB, OrientDB, Oracle Multimodel. Ventajas: adaptabilidad y reducción de la fragmentación de datos.

Tema 03 · MongoDB

MongoDB: Gestor
NoSQL Documental

📄 Definición
¿Qué es MongoDB?

Sistema de gestión NoSQL orientado a documentos, desarrollado en 2009 por MongoDB Inc. Los datos se almacenan en colecciones (equivalente a tablas), y cada documento en formato JSON/BSON permite almacenar objetos complejos y jerárquicos sin esquemas predefinidos.

⚡ Características Principales
Ventajas clave
✦ Esquema flexible: sin estructura rígida
✦ Escalabilidad horizontal: sharding en múltiples servidores
✦ Alto rendimiento: lecturas y escrituras rápidas
✦ Alta disponibilidad: replica sets
✦ Compatibilidad: Java, Python, Node.js, C#
✦ Herramientas: Compass (GUI), Atlas (nube)
🏗️ Arquitectura
Componentes principales
✦ Colecciones y documentos: almacenamiento dinámico
✦ Replica sets: replicación para redundancia
✦ Sharding: partición horizontal para Big Data
✦ Drivers: conectores para distintos lenguajes
MongoDB 5.x/6.x integra funciones de time-series, vistas materializadas y optimizaciones para aplicaciones en la nube.
✅ Conclusión MongoDB

MongoDB es un referente entre los gestores NoSQL, combinando flexibilidad, escalabilidad y rendimiento. Su modelo documental basado en JSON lo convierte en la elección ideal para proyectos modernos que requieren manejar datos complejos y dinámicos, consolidándose como una herramienta híbrida que responde a las demandas del ecosistema digital actual.

🌐 Importancia en sectores
Aplicaciones reales
✦ Comercio electrónico: catálogos con descripciones variables
✦ Redes sociales: publicaciones con comentarios y reacciones en estructuras flexibles
✦ Analítica de datos: integración de información semiestructurada de logs o sensores IoT

Tema 05 · Compatibilidad

Compatibilidad con
Diferentes Arquitecturas

🏛️ Relacionales (RDBMS)

Basados en tablas con filas y columnas. Ofrecen transacciones ACID. Adecuados para arquitecturas centralizadas, sistemas financieros y empresariales con estructuras de datos bien definidas. Mejor compatibilidad con arquitecturas cliente-servidor y aplicaciones tradicionales.

🌐 No Relacionales (NoSQL)

Se orientan a documentos, columnas, grafos o pares clave-valor. Priorizan escalabilidad horizontal y flexibilidad de esquemas. Ideales para arquitecturas distribuidas, sistemas en tiempo real, aplicaciones web y móviles, e integración con Big Data.

☁️ DBMS en la Nube

Plataformas como Amazon RDS, Google Cloud SQL y Azure SQL Database ofrecen RDBMS administrados. Servicios como MongoDB Atlas facilitan la implementación NoSQL con escalabilidad automática. La nube proporciona elasticidad, facturación bajo demanda y gestión simplificada.

⚖️ Factores de Elección
Escalabilidad, Rendimiento, Costo, Soporte
✦ Escalabilidad: RDBMS = vertical · NoSQL = horizontal
✦ Rendimiento: RDBMS óptimo en transacciones · NoSQL superior con grandes volúmenes semiestructurados
✦ Costo: Oracle/SQL Server requieren licencias · MySQL/PostgreSQL/MongoDB reducen costos iniciales
✦ Comunidad: PostgreSQL y MongoDB aseguran actualizaciones y recursos de aprendizaje
🔮 Tendencias Actuales
DBMS híbridos, Microservicios y Big Data
✦ DBMS híbridos: capacidades relacionales y no relacionales (Oracle Multimodelo, PostgreSQL con JSONB)
✦ Big Data: Cassandra y HBase compatibles con Hadoop y Spark
✦ Microservicios: DBMS diseñados para Docker y Kubernetes
La tendencia actual combina ambos enfoques en entornos híbridos y en la nube, buscando aprovechar lo mejor de cada modelo.

📝 Ejercicio Propuesto · Tema I
Proyecto: Sistema de Gestión Académica con MySQL

Imagina que un startup necesita gestionar ventas en línea y almacenar datos de clientes, productos e interacciones en redes sociales.

¿Qué tipo de DBMS elegirías: relacional, no relacional o híbrido?
Se recomienda una arquitectura híbrida: usar MySQL/PostgreSQL (relacional) para datos transaccionales de ventas y clientes (que requieren consistencia ACID), y MongoDB (NoSQL) para almacenar datos de interacciones en redes sociales en formato flexible. Esto combina lo mejor de ambos modelos.
Justificación con al menos 3 argumentos
1. Rendimiento: MySQL/PostgreSQL optimizan consultas transaccionales con índices B-Tree, mientras MongoDB gestiona documentos JSON sin conversión de formato.
2. Escalabilidad: MongoDB permite sharding horizontal para manejar millones de interacciones sociales sin degradar el rendimiento.
3. Estructura de datos: Los pedidos y clientes tienen estructura definida (tablas), pero las interacciones sociales son variables y semiestructuradas, ideales para documentos BSON.
📝 Ejercicio Propuesto · Tema II-IV
Informe de Análisis Técnico por Escenarios
Comparativo técnico entre SQL Server, MySQL, PostgreSQL y Oracle para un sistema hospitalario
Recomendación: Oracle Database para el sistema hospitalario principal, por su soporte multimodelo (relacional, documental, espacial), altísima disponibilidad con RAC, cifrado integral, control de acceso granular y soporte para Big Data. Para módulos secundarios como reportes académicos se recomienda PostgreSQL por su relación costo-beneficio y cumplimiento SQL.
Proyecto aplicado: BD para sistema académico con gestión de estudiantes, cursos y notas
Gestor elegido: PostgreSQL. Razones: (1) cumple estándares SQL con soporte de tipos avanzados como arrays y JSON para notas flexibles; (2) escalabilidad vertical y horizontal para crecer con el número de estudiantes; (3) seguridad avanzada con SSL y autenticación GSSAPI; (4) herramienta pgAdmin facilita la administración; (5) código abierto sin costos de licencia, ideal para entornos académicos.
